Backend — packages/

There is no separate API service. “One backend” means one shared library that App Router server components import and read Postgres with directly.
packages/core@femi9/core — the actual backend. Auth, sessions, Razorpay, pricing, geo, OTP, Thara + src/services/* (cart, checkout, orders, products, subscriptions, blog…) and src/services/admin/*.
Import by subpath, never the barrel: import { getOrders } from '@femi9/core/services/admin/orders'
packages/db@femi9/db — the one Prisma schema + migrations. Exposes dbFor(brand)
packages/db-platform@femi9/db-platform — admin identity in its own schema; generates to generated/ (gitignored)
HTTP surfaceEach app's own route handlers — e.g. apps/femi9-web/app/api/{auth, cart, checkout, payments, webhooks, cron, …}
One Postgres, three schemas: femi9 · lumi9 · platform. Isolation lives in the connection string, not a where clause somebody can forget.

Env — no root .env, it's per-app

apps/femi9-web/.env — DATABASE_URL, DIRECT_URL, AUTH_SECRET, Razorpay, Resend, Google OAuth, TEST_DATABASE_URL, THARA_ENABLED
apps/lumi9-web/.env — DATABASE_URL_LUMI9, AUTH_SECRET, RESEND_API_KEY_LUMI9 / EMAIL_FROM_LUMI9, Razorpay, SITE_URL
apps/admin/ — no .env. In prod reads DATABASE_URL_PLATFORM + ADMIN_AUTH_SECRET from the task definition / Secrets Manager. Create one locally.
The canonical list (~60 vars — brand-suffixed *_FEMI9 / *_LUMI9 / *_PLATFORM, Sentry, MSG91, Upstash, CYCLE_DATA_ENCRYPTION_KEY, CRON_SECRET) is apps/femi9-web/.env.example — the reference for all three apps.

Commands & two gotchas

npm installalways at the root. One hoisted lockfile; apps have none
npm run dev:femi9:3000
npm run dev:lumi9:3001
npm run dev:admin:3002
npm run buildturbo — all apps
npm test in femi9-web truncates every table. Never run it with a .env pointing at staging or production.
Docker builds from the repo root, not from the app — npm ci needs the hoisted lockfile.
